# 生产部署说明

**文档索引**：[README.md](./README.md)

本文说明 monorepo 各组件在生产环境的域名、进程形态与发布脚本。环境变量使用各包下的 `.env.production`（**勿提交含密钥文件**；从 `.env.example` 复制后在服务器填写。进程 `ENV=production` 时 backend 才加载该文件）。

---

## 1. 域名与流量

| 入口 | 主机 / 路径 | 后端 |
|------|-------------|------|
| 登录 | `https://app.aperix.cn/auth/login` | frontend 静态 SPA |
| 控制台 | `https://app.aperix.cn/`、`/billing/plan` 等 | 同上 |
| API | `https://app.aperix.cn/api/v1/...` | FastAPI（本机 uvicorn，默认 `:8000`） |
| 官网 | `https://www.aperix.cn` | website（Node，默认本机 `:4321`） |
| CMS | `https://www.aperix.cn/cms` | Payload（Node，默认本机 `:3000`） |

```text
Browser → Nginx
  app.aperix.cn /     → frontend/dist（SPA try_files）
  app.aperix.cn /api  → 127.0.0.1:8000
  www.aperix.cn /_next/ → 127.0.0.1:3000（payload，Admin 静态资源）
  www.aperix.cn /cms    → 127.0.0.1:3000（payload）
  www.aperix.cn /       → 127.0.0.1:4321（website）
```

营销域**不要**再把 `/app`、`/auth` 指到 React；控制台只挂在 `app.aperix.cn`。

依赖：PostgreSQL、Redis（backend / Celery）；官网与 CMS 另有各自 DB 配置，见各包 `.env.production`。

## 2. 发布脚本（仓库根目录）

| 脚本 | 产物 / 进程 | 说明 |
|------|-------------|------|
| [`rebuild-and-restart-frontend.sh`](../rebuild-and-restart-frontend.sh) | `frontend/dist` | 用 `node:22-bookworm` **一次性** `npm ci && build`；无常驻容器，由 Nginx 托管 |
| [`rebuild-and-restart-website.sh`](../rebuild-and-restart-website.sh) | 容器 `aperix-website` | build 后 restart；首次 `docker run` 常驻 Node |
| [`rebuild-and-restart-payload.sh`](../rebuild-and-restart-payload.sh) | 容器 `aperix-payload` | 同上；依赖仓库内 [`payload/media/`](../payload/media/)（CMS 上传图随 git 下发） |
| [`rebuild-and-restart-backend.sh`](../rebuild-and-restart-backend.sh) | systemd `aperix-backend` | 检查 Python ≥ 3.12 → venv → alembic → 启停 `start_backend.sh`（API + Celery Worker + Beat） |

典型顺序（有依赖变更时）：先 backend（含迁移），再 frontend / website / payload。

```bash
bash rebuild-and-restart-backend.sh
bash rebuild-and-restart-frontend.sh
bash rebuild-and-restart-website.sh
bash rebuild-and-restart-payload.sh
```

Backend 详情见 [backend/README.md](../backend/README.md)「生产部署（systemd）」：

```bash
systemctl status aperix-backend
journalctl -u aperix-backend -f
```

## 3. 前置：`node:22-bookworm` 镜像（系统过旧无法直拉时）

frontend / website / payload 的构建与运行镜像均为 **`node:22-bookworm`**（Node ≥ 22）。若服务器系统过旧、无法直接 `docker pull`（或官方源不可达），在**本机**拉镜像、打包上传，再在服务器 `docker load`。

### 3.1 本机生成

```bash
# 1. 拉镜像
docker pull node:22-bookworm

# 2. 导出并压缩
docker save node:22-bookworm | gzip > node-22-bookworm.tar.gz
```

文件生成在当前目录，大小大约 **300MB～1GB**。

### 3.2 传到服务器

```bash
scp node-22-bookworm.tar.gz root@你的服务器IP:/tmp/
```

### 3.3 服务器上导入

```bash
gunzip -c /tmp/node-22-bookworm.tar.gz | docker load
docker images | grep node
```

确认列表中有 `node` / `22-bookworm` 后，再执行上文的 `rebuild-and-restart-frontend.sh`、`website`、`payload` 脚本。

## 4. Backend 补充

- 需本机 **Python ≥ 3.12**、`systemctl`；脚本会建 `backend/.venv` 并安装依赖。
- 运行用户可用 `APERIX_SERVICE_USER` 覆盖（默认当前用户 / `SUDO_USER`）。
- 仅开 API、不开 Celery 时，采样任务会停在 `queued`；生产单元通过 `start_backend.sh` 一并拉起 Worker（分池）与 Beat。

## 5. Nginx：路径如何解析

容器起来后（见 §2），本机监听为：

| 容器 | 本机端口 | 进程 |
|------|----------|------|
| `aperix-payload` | `127.0.0.1:3000` | Next.js + Payload（`admin`/`api` 前缀均为 `/cms`） |
| `aperix-website` | `127.0.0.1:4321` | Astro Node（`dist/server/entry.mjs`） |

Nginx 只做 **反代**，不要把营销站主流量落到 `root` 静态目录（`root` 仅留给证书校验 `.well-known` 等即可）。

### 5.1 匹配顺序（重要）

必须用 `^~`，且 **更具体的路径写在前面**，避免被 `location /` 抢走：

| 优先级 | `location` | 上游 | 原因 |
|--------|------------|------|------|
| 1 | `^~ /_next/` | `:3000` Payload | Admin 的 CSS/JS/字体在 Next 静态路径，浏览器请求 `/_next/...`，**不能**进 Astro |
| 2 | `^~ /cms` | `:3000` Payload | Admin、`/cms/api`、媒体等 |
| 3 | `^~ /`（或 `/`） | `:4321` website | 官网其余路径 |

反向：若先 `location /` → Astro，则 `/cms`、`/_next` 会 404 或错站。

反代头建议统一带上：`Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host`（Payload / Astro 生成绝对 URL、Cookie、HTTPS 判断依赖它们）。`client_max_body_size` 建议 ≥ `50m`（CMS 媒体上传）。

### 5.2 营销域示例（宝塔 / 面板可改 `server_name` 与证书路径）

以下结构对齐常见「Astro 官网 + Payload `/cms`」反代（参考同构站点配置），`server_name` 为 `www.aperix.cn`：

```nginx
server
{
    listen 80;
    listen 443 ssl http2;
    server_name www.aperix.cn;
    index index.html index.htm;
    # 仅给 .well-known / 少数本地文件；主站走反代
    root /www/wwwroot/www.aperix.cn;

    # 证书申请与面板扩展（按你面板实际路径保留）
    # include /www/server/panel/vhost/nginx/well-known/www.aperix.cn.conf;
    # include /www/server/panel/vhost/nginx/extension/www.aperix.cn/*.conf;

    # HTTP → HTTPS（保留 .well-known 走 80 校验）
    set $isRedcert 1;
    if ($server_port != 443) {
        set $isRedcert 2;
    }
    if ( $uri ~ /\.well-known/ ) {
        set $isRedcert 1;
    }
    if ($isRedcert != 1) {
        rewrite ^(/.*)$ https://$host$1 permanent;
    }

    ssl_certificate     /www/server/panel/vhost/cert/www.aperix.cn/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/www.aperix.cn/privkey.pem;
    # …其余 ssl_* / HSTS 按面板默认即可

    client_max_body_size 50m;

    location ~ \.well-known {
        allow all;
    }

    # Next.js 静态资源（CSS/JS/字体）——必须指到 Payload
    location ^~ /_next/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
    }

    # —— Payload CMS（Admin / API / 媒体）——
    # ^~ 避免被下面敏感文件正则抢掉
    location ^~ /cms {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_read_timeout 300s;
        proxy_buffering off;
    }

    # —— Astro 官网 ——
    location ^~ / {
        proxy_pass http://127.0.0.1:4321;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
    }

    access_log  /www/wwwlogs/www.aperix.cn.log;
    error_log   /www/wwwlogs/www.aperix.cn.error.log;
}
```

发布后自检：

```bash
curl -sI https://你的营销域/cms          # 应进 Payload（非 Astro 404）
curl -sI https://你的营销域/_next/static # 应 200/304 或由 Payload 处理
curl -sI https://你的营销域/             # Astro 首页
```

官网构建侧：`PAYLOAD_API_URL=/cms/api`（同域相对路径即可）。Payload：`PAYLOAD_SERVER_URL=https://你的营销域`（或带 www 的正式 URL），与公网一致。

### 5.3 控制台域 `app.aperix.cn`（对照）

与营销域拆开，**不要**在营销域反代 `/app`、`/auth`：

| 路径 | 上游 |
|------|------|
| `/api/` | `127.0.0.1:8000`（FastAPI / systemd `aperix-backend`） |
| `/` 及其它 | `frontend/dist` 静态，`try_files $uri $uri/ /index.html` |

TLS、证书与 `server_name` 由运维在面板维护，不在本仓库强制落盘。
