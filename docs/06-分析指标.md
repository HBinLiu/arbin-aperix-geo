# 分析指标：定义与实现说明

**文档索引**：[README.md](./README.md) · 所属流程：**04 Analysis（04a）** · [05-诊断流程.md](./05-诊断流程.md)

本文档说明 Aperix GEO 控制台核心指标的**业务含义**、**统计公式**与**当前代码实现**。验收口径与产品文案以本文为准。

本指标集归属品牌分析流水线 **第 04 步 Analysis（声量聚合诊断）** 的 **04a 核心指标** 部分；全流程见 [05-诊断流程.md](./05-诊断流程.md)（**03 Clean** 产出 `parsed`，**04 Analysis** 聚合）。

相关代码：

| 层级 | 路径 | 职责 |
|------|------|------|
| 采样 | `tasks/sampling.py` | 批量调用 LLM，写入 `tb_llm_responses` |
| 解析 | `services/sampling/parser.py` | 将 `raw_text` 转为 `parsed`（JSONB） |
| 情感 | `services/sampling/sentiment.py` | LLM 裁判式品牌情感打分（0~100） |
| 聚合 | `services/analysis.py` | 按时间窗对 `parsed` 做只读统计 |
| API | `api/routes/analysis.py` | `overview`、`rank`、各分析子页等 |

---

## 1. 总体数据流

```text
01 Verify   → 主体 / 竞品 / 主题 / 提示词确认
02 Dispatch → SamplingJob → LLMResponse.raw_text
03 Clean    → parse_llm_output() → LLMResponse.parsed（结构化信号）
04 Analysis → compute_subject_metrics() / _rank_from_rows() → 看板 API
```

```text
Prompt × Platform（渠道）
    → SamplingJob
        → LLMResponse（status=success, raw_text, parsed）
            → 指标聚合（Subject + 时间窗 [from, to] + 可选筛选）
                → 看板 API
```

### 1.1 统一分母

- 默认：时间窗内、`SamplingJob.subject_id` 匹配、`LLMResponse.status = success` 且 `parsed` 非空的回复条数，记为 **N**。
- 渠道筛选：`platform IN (...)`（如 `doubao`、`deepseek`，与主体 `sampling_platforms` 一致）。
- 可选：`topic_id`、`prompt_id` 通过 `Prompt` 表关联过滤。

### 1.2 主体与竞品

| `Subject.type` | 自有实体（解析用） | 竞品实体（每条 `tb_competitors` 记录） |
|----------------|-------------------|--------------------------------------|
| `brand` / `domain` | `brand` + `domain` + `aliases[]`（去重） | `brand` + `domain` 合并为**单一 label**（优先 `brand`） |

解析阶段为每条成功回复产出结构化 `parsed`；聚合阶段只做加总/平均，不在 API 层重复解析 `raw_text`。

## 2. 六大指标对照表

| 产品名 | API 字段 | 核心问题 | 实现状态 |
|--------|----------|----------|----------|
| 可见度 | `visibility_rate` | 有多少条回复提到了我？ | ✅ `compute_subject_metrics` |
| AI 提及 | `mention_rate` | 平均每条回复里品牌被提到几次？ | ✅ 按提及次数 / N |
| 声量份额 | `share_voice` | 提及声量中我占多少？ | ✅ 按提及次数占比 |
| 平均排名 | `average_rank` | 在回答里我排第几？ | ✅ `rank_own` 均值 |
| 引用率 | `citation_rate` | 指向您域名的来源页是否提及品牌？ | ✅ C 口径 |
| 情感倾向 | `sentiment_score` | 提到我时态度如何？ | ✅ LLM 裁判，0~100 分 |

> **命名说明**：产品文案中的「AI 提及强度」对应 API 字段 `mention_rate`（非 `mention_intensity`）。

## 3. 单条回复（per-response）信号

由 `parse_llm_output()`（`services/sampling/parser.py`）写入 `parsed`：

```json
{
  "mentions_own": true,
  "mention_count_own": 2,
  "mentions_competitors": { "竞品A": true, "竞品B": false },
  "mention_counts_competitors": { "竞品A": 1, "竞品B": 0 },
  "rank_own": 1,
  "rank_hints_first_index": { "自有品牌": 120, "竞品A": 450 },
  "cited_own_domain": true,
  "has_own_domain_link": true,
  "citation_urls_own": ["https://example.com/page"],
  "citation_sources": [
    { "url": "https://example.com/page", "target": "own", "fetch_ok": true, "page_mentions_brand": true }
  ],
  "cited_competitors_on_source": { "竞品A": false },
  "has_competitor_domain_links": { "竞品A": false },
  "sentiment_own": "positive",
  "sentiment_score_own": 85.0,
  "sentiment_reason_own": "整体语气积极，明确推荐该产品",
  "sentiment_competitors": { "竞品A": "neutral" },
  "sentiment_scores_competitors": { "竞品A": 55.0 },
  "sentiment_reasons_competitors": { "竞品A": "客观对比，未明显贬损" },
  "sentiment_source": "llm",
  "urls": [],
  "url_hosts": []
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `mention_count_own` | int | 正文中自有品牌/域名（含别名）子串出现次数（不区分大小写） |
| `mention_counts_competitors` | dict[str,int] | 各竞品 label 的提及次数（brand+domain 合并计数，与排行榜 label 一致） |
| `rank_own` | int \| null | 本条回复内，按**首次出现位置**排序后的名次，1=最先；未提及为 `null` |
| `cited_own_domain` | bool | **C 口径**：至少一条指向自有根域的来源 URL，其**页面正文**提及品牌 |
| `has_own_domain_link` | bool | 回复正文中存在指向自有根域的来源 URL |
| `citation_sources` | array | 已抓取的来源页明细（`fetch_ok`、`page_mentions_brand`） |
| `cited_competitors_on_source` | dict[str,bool] | 各竞品：来源页正文是否提及该竞品 |
| `sentiment_own` | enum | `positive` / `neutral` / `negative` |
| `sentiment_score_own` | float \| null | **0~100**，越高越正面；LLM 裁判打分 |
| `sentiment_reason_own` | string \| null | LLM 裁判给出的一句话理由（`reason` 字段） |
| `sentiment_scores_competitors` | dict[str,float] | 各竞品情感分（0~100） |
| `sentiment_reasons_competitors` | dict[str,string] | 各竞品情感理由 |
| `sentiment_source` | string | `llm` / `none` / `failed` |

### 3.1 解析规则摘要

| 信号 | 算法 |
|------|------|
| 主体提及 | 对 `brand` + `domain` + `aliases` 子串计数（不区分大小写） |
| 竞品提及 | 每条竞品记录：`brand` + `domain` 合并匹配；label 优先 `brand`；正文无命中时可用 URL 主机名匹配 `domain` |
| 排名 | 收集所有被提及候选的首次字符位置，升序排名；`rank_own` 为自有实体最佳名次 |
| 引用 | 提取正文 URL；对指向自有/竞品域名的链接 **抓取来源页**（httpx），检测页面正文是否提及品牌 |
| 情感 | 主体或竞品被提及时，调用 `analyze_brand_sentiment()`；prompt 见 `services/providers/prompts.py` |

### 3.2 情感打分（LLM 裁判）

- 实现：`services/sampling/sentiment.py` → `analyze_brand_sentiment()`
- 模型：DeepSeek（`chat_completion`，`temperature=0`，`json_mode=true`）
- 分值：**0~100**（50=中立，100=极正面，0=极负面）
- 无词典兜底：LLM 失败时 `sentiment_score_own` 为 `null`，`sentiment_source=failed`
- 历史数据：若 `parsed` 中存的是 0~1 小数，读取时由 `utils/sentiment.sentiment_points()` 自动 ×100

## 4. 各指标定义与公式

### 4.1 可见度（Visibility）

**含义**：至少提及一次自有品牌的 AI 回复占全部成功回复的比例。

```text
可见度 = |{ r ∈ R : mentions_own(r) }| / N
```

- 实现：`compute_subject_metrics().visibility_rate`
- 前端：×100 展示为百分比（如 `0.65` → `65.0%`）
- `N = 0` → `null`

---

### 4.2 AI 提及（Mention Rate）

**含义**：品牌在回答正文中被讨论的**频繁程度**（强度）。

| | 可见度 | AI 提及 |
|--|--------|---------|
| 粒度 | 每条回复 0/1 | 每条回复 ≥0 的计数 |
| 公式 | 提及条数 / N | Σ mention_count_own / N |

```text
AI 提及 = ( Σ_{r∈R} mention_count_own(r) ) / N
```

- 实现：`compute_subject_metrics().mention_rate`
- 若 `mentions_own=true` 但计数为 0，聚合时按 1 计（兜底）
- 前端：×100 展示

---

### 4.3 声量份额（Share of Voice）

**含义**：在「自有 + 已配置竞品」的**提及次数**总量中，自有品牌所占比例。

```text
总声量 = Σ mention_count_own + Σ_{c∈竞品} mention_count_competitor(c)
声量份额 = Σ mention_count_own / 总声量    （总声量 > 0）
```

- 实现：`compute_subject_metrics().share_voice`
- 按**提及次数**，非按「多少条回复提到」
- 总声量为 0 → `null`
- 竞品对比榜（`/rank`）中，各品牌 `share_voice[label]` 为同理按 label 拆分

---

### 4.4 平均排名（Average Rank）

**含义**：按品牌/竞品**首次出现字符位置**排序得到名次；数值越小越好（1=最先被提到）。

**单条回复算法**（`_compute_rank_own`）：

1. 候选 = 自有名称 + 竞品 brand/domain
2. 取各候选 `first_index`（`rank_hints_first_index`）
3. 仅保留被提及的候选，按 index 升序赋名次 1, 2, …
4. `rank_own` = 自有实体中最佳（最小）名次

**聚合**：

```text
平均排名 = mean(rank_own(r)) over r where rank_own(r) is not null
```

- 实现：`compute_subject_metrics().average_rank`（仅主体）
- 竞品对比：`_accumulate_average_ranks()` 按 label 分别求均值
- 保留 2 位小数

---

### 4.5 引用率（Citation Rate）

**含义（C 口径）**：在 AI 回复给出的、指向**您域名**的来源链接中，来源页正文**提及您品牌**的占比。反映内容可信度与将 AI 浏览量转化为站点流量的能力。

**概述页**：

```text
引用率 = |{ r : cited_own_domain(r) }| / |{ r : has_own_domain_link(r) }|
```

- `has_own_domain_link`：回复正文含指向自有根域的 URL
- `cited_own_domain`：至少一条上述 URL 的来源页正文提及品牌（brand / domain / aliases）
- 实现：`compute_subject_metrics().citation_rate`；解析见 `services/sampling/citation_page.py`
- brand 主体需配置 `website_url` 才能识别自有域名
- 无自有域来源链接时返回 `null`
- 配置：抓取见 `PAGE_CRAWL_*`；引用 LLM 见 `CITATION_TEXT_SNIPPET_CHARS`、`CITATION_PAGE_GEO_*`、超时复用 `DEEPSEEK_CHAT_TIMEOUT_S`

**全量引用覆盖（可选字段）**：

```text
citation_coverage = |{ r : cited_own_domain(r) }| / N
```

- 仅 `domain` 主体或配置了 `website_url` 的 brand 主体返回

**竞品对比榜 `citation_share`（注意口径差异）**：

```text
citation_share[label] = 来源页提及该品牌的回复数 / N
```

- 主体：`cited_own_domain`；竞品：`cited_competitors_on_source[label]`
- 分母为**全部 N 条回复**，与概述页 `citation_rate` 分母不同

---

### 4.6 情感倾向（Sentiment）

**含义**：AI 在提及自有品牌时的态度；**0~100 分**，越高越正向。

```text
情感得分 = mean(sentiment_score_own(r)) over r where mentions_own(r) and score is not null
```

- 实现：`compute_subject_metrics().sentiment_score`（保留 1 位小数）
- 同时返回 `sentiment_count`：`positive` / `neutral` / `negative` 回复条数
- 竞品对比：`_accumulate_sentiment_by_label()`，读取 `sentiment_scores_competitors`
- 前端标签：≥55 正面，45~55 中立，<45 负面

## 5. 聚合服务与 API

### 5.1 概述 `GET /subjects/{id}/overview`

由 `build_overview()` → `compute_subject_metrics()` 返回：

```json
{
  "window": { "from": "...", "to": "..." },
  "filters": { "platforms": ["deepseek"], "topic_id": null },
  "visibility_rate": 0.65,
  "mention_rate": 1.12,
  "share_voice": 0.41,
  "average_rank": 1.8,
  "citation_rate": 0.33,
  "sentiment_score": 72.5,
  "sentiment_count": { "positive": 40, "neutral": 25, "negative": 3 },
  "citation_coverage": 0.15
}
```

> 比率类字段（可见度、声量份额、引用率等）API 为 0~1 小数；情感 `sentiment_score` 为 **0~100**。

### 5.2 竞品对比 `GET /subjects/{id}/rank`

由 `build_rank()` → `_rank_from_rows()` 返回主体 + 各竞品：

| 字段 | 含义 |
|------|------|
| `visibility_share` | 提及该品牌的回复数 / N |
| `mention_rate` | 该品牌提及次数合计 / N |
| `share_voice` | 该品牌提及次数 / 全部品牌提及次数之和 |
| `average_rank` | 该品牌名次均值 |
| `citation_share` | 引用该品牌域名的回复数 / N |
| `sentiment_score` | 该品牌 LLM 情感分均值（0~100） |

### 5.3 分析子页端点

| 端点 | 页面 | 说明 |
|------|------|------|
| `GET /subjects/{id}/overview` | 概述 | 六大 KPI |
| `GET /subjects/{id}/visibility-analysis` | 可见度 | 品牌榜、可见度/提及/排名日趋势、主题排名 |
| `GET /subjects/{id}/topics-performance` | 提示词 | 按主题拆六大 KPI |
| `GET /subjects/{id}/prompts-performance` | 提示词 | 按提示词拆六大 KPI |
| `GET /subjects/{id}/platform-matrix-analysis` | AI 平台 | 平台 × 指标矩阵 |
| `GET /subjects/{id}/sentiment-analysis` | 情感倾向 | 总分、正/中/负日分布、平台排名、回复明细 |
| `GET /subjects/{id}/citation-analysis` | 引用率 | 品牌引用份额趋势、域名/URL 明细 |
| `GET /subjects/{id}/rank` | 排行榜 | 主体 vs 竞品六维对比 |

公共查询参数：`from`、`to`；可选 `platform`（可重复）、`topic_id`、`prompt_id`。

### 5.4 辅助诊断指标

| 指标 | 场景 | 公式 |
|------|------|------|
| `brand_gap_rate` | 内容机会 | `1 - 提及主体回复数 / 该提示词×平台组总数` |
| `source_gap_rate` | 内容机会 | `1 - cited_own_domain 回复数 / 总数` |
| 引用域名/URL 榜 | 引用页 | 统计 `url_hosts` / `urls` 出现频次 / N |
| 情感日趋势 | 情感页 | 按日平均 `sentiment_score_own` |
| 情感分布 | 情感页 | 按日统计 positive/neutral/negative 占比 |

## 6. 前端展示规则

| 指标类型 | API 值域 | 前端展示 |
|----------|----------|----------|
| 比率类（可见度、声量、引用率等） | 0~1 | ×100 + `%` |
| 平均排名 | 浮点数 | 原值，如 `1.8` |
| 情感倾向 | **0~100** | 直接显示，如 `72.5`；兼容旧 0~1 数据自动 ×100 |

## 7. 质量与已知局限

| 项 | 说明 |
|----|------|
| 启发式解析 | 子串匹配无法处理代词、表格、多语言变体 |
| 排名 | 基于首次出现位置，不等同于「推荐列表中的第 N 项」 |
| 引用 | 竞品引用靠 URL 主机名是否含竞品域名字符串，较粗糙 |
| 情感 | 依赖二次 LLM 调用；失败则该条无分；有 API 成本 |
| 引用口径 | 概述 `citation_rate` 与排行榜 `citation_share` 分母不同，解读时需区分 |
| 渠道 | 多平台样本量不均时，建议分平台展示 |
| 采样偏差 | 指标仅反映已配置 Prompt × 平台的问答分布 |
