# 分析指标：定义与实现说明

**文档索引**：[README.md](./README.md) · 所属流程：**04 Analysis（04a）** · [05-诊断流程.md](./05-诊断流程.md)

本文档说明 Aperix GEO 控制台六大核心指标的**业务含义**、**统计公式**、**与现有代码的关系**及**推荐实现路径**。验收口径与产品文案以本文为准；实现代码以 `backend/src/aperix_geo/services/parser.py`、`analysis.py` 为落点。

本指标集归属品牌分析流水线 **第 04 步 Analysis（声量聚合诊断）** 的 **04a 核心指标** 部分；全流程见 [05-诊断流程.md](./05-诊断流程.md)（**03 Clean** 产出 `parsed`，**04 Analysis** 聚合）。

相关代码：

| 层级 | 路径 | 职责 |
|------|------|------|
| 采样 | `tasks/sampling.py` | 批量调用 LLM，写入 `tb_llm_responses` |
| 解析 | `services/parser.py` | 将 `raw_text` 转为 `parsed`（JSONB） |
| 聚合 | `services/analysis.py` | 按时间窗对 `parsed` 做只读统计 |
| API | `api/routes/analysis.py` | `overview`、`leaderboard` 等 |

---

## 1. 总体数据流

```text
01 Verify   → 主体 / 竞品 / 主题 / 提示词确认
02 Dispatch → SamplingJob → LLMResponse.raw_text
03 Clean    → LLMResponse.parsed（结构化信号）
04 Analysis → 指标聚合（Subject + 时间窗 + 筛选）→ 看板 API
```

```text
Prompt × Platform（渠道）
    → SamplingJob
        → LLMResponse（status=success, raw_text, parsed）
            → 指标聚合（Subject + 时间窗 [from, to] + 可选筛选）
                → 看板 API
```

**统一分母（建议）**

- 默认：时间窗内、`SamplingJob.subject_id` 匹配、且 `LLMResponse.status = success` 的回复条数，记为 **N**。
- 「所选渠道」：增加 `platform IN (...)`（按 `LLMResponse.platform` 筛选，值为平台标识如 `doubao`、`deepseek`；与主体 `sampling_platforms` 配置一致）。
- 可选扩展：`topic_id`、`prompt_id` 通过 `Prompt` 表关联过滤。

**主体类型**

| `Subject.type` | 自有实体 | 竞品实体 |
|----------------|----------|----------|
| `brand` | `brand_canonical` + `aliases` | `CompetitorBrand.name`、`CompetitorDomain`（域名/链接维度） |
| `domain` | `domain` + `aliases` | 同上 |

解析阶段应为每条成功回复产出**结构化信号**（见 §3），聚合阶段只做加总/平均，避免在 API 里重复解析 `raw_text`。

## 2. 六大指标对照表

| 产品名 | 建议 API 字段 | 核心问题 | 与现有实现 |
|--------|---------------|----------|------------|
| 可见度 | `visibility_rate` | 有多少条回复提到了我？ | ✅ 已有（`mentions_own / N`） |
| AI 提及 | `mention_intensity` | 提到我的**强度/频次**如何？ | ⚠️ 与可见度混用，需新增计数 |
| 声量份额 | `share_of_voice` | 提及声量中我占多少？ | ⚠️ `leaderboard` 按「条数」近似，非声量 |
| 平均排名 | `average_rank` | 在回答里我排第几？ | ⚠️ 仅有 `rank_hints_first_index`，非名次 |
| 引用率 | `citation_rate` | 提到我时是否带本站链接？ | ⚠️ 仅有 `cited_own_domain`（按条） |
| 情感倾向 | `sentiment_score` | 提到我时态度如何？ | ⚠️ 整段 `sentiment_crude`，非品牌局部 |

## 3. 单条回复（per-response）信号设计

在 `parse_llm_output()` 返回的 `parsed` 中扩展（向后兼容：旧数据缺字段时聚合层按默认值处理）。

```json
{
  "mentions_own": true,
  "mention_count_own": 2,
  "mention_counts_competitors": { "竞品A": 1, "竞品B": 0 },
  "rank_own": 1,
  "rank_hints_first_index": { "自有品牌": 120, "竞品A": 450 },
  "cited_own_domain": true,
  "citation_urls_own": ["https://example.com/page"],
  "sentiment_own": "positive",
  "sentiment_score_own": 0.72,
  "sentiment_crude": "neutral",
  "urls": [],
  "url_hosts": []
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `mention_count_own` | int | 正文中自有品牌/域名（含别名）出现次数（去重策略见 §4.2） |
| `mention_counts_competitors` | dict[str,int] | 各竞品名称/域名出现次数 |
| `rank_own` | int \| null | 本条回复内，按**首次出现位置**排序后的名次，1=最先被提及；未提及为 `null` |
| `cited_own_domain` | bool | 是否出现指向自有根域名的链接（domain 主体；brand 主体需配置关联网站域） |
| `sentiment_own` | enum | `positive` / `neutral` / `negative`，仅针对含品牌提及的句子或片段 |
| `sentiment_score_own` | float | 建议 0~1，越高越正面；由 `sentiment_own` 映射或模型打分 |

## 4. 各指标定义与公式

### 4.1 可见度（Visibility）

**含义**：在所选时间窗与渠道内，**至少提及一次**自有品牌的 AI 回复占全部成功回复的比例。越高表示曝光面越广。

**公式**：

```text
可见度 = |{ r ∈ R : r.parsed.mentions_own = true }| / N
```

**实现要点**：

- 与当前 `build_overview().visibility_rate` 一致。
- 前端展示为百分比：`round(rate * 100, 2)`。

**边界**：

- `N = 0` 时返回 `null`，UI 显示「暂无数据」。

---

### 4.2 AI 提及（AI Mention / Mention Intensity）

**含义**：反映品牌在回答正文中被讨论的**频繁程度**（强度），而非「是否出现」。数值越高，表示 AI 更倾向于反复、主动地讨论该品牌。

**与可见度的区别**：

| | 可见度 | AI 提及 |
|--|--------|---------|
| 粒度 | 每条回复 0/1 | 每条回复 ≥0 的计数 |
| 典型公式 | 提及条数 / N | 平均提及次数 或 提及总次数 / N |

**推荐公式（MVP）**：

```text
AI 提及强度 = ( Σ_{r∈R} mention_count_own(r) ) / N
```

可选补充（V1）：

```text
提及率（至少一次）= 可见度
平均每提及回复中的次数 = Σ mention_count_own / |{r : mentions_own}|
```

**实现要点**：

- 解析层：对 `brand_canonical`、`aliases`、domain 主体下的 `domain` 做子串计数（注意大小写、全角；竞品词边界可用简单分词或 `\b` 仅英文）。
- 避免把 URL 里的域名重复计为「品牌提及」时可配置：默认正文计数包含域名文字，链接主机单独走引用率。

---

### 4.3 声量份额（Share of Voice, SOV）

**含义**：在「自有 + 已配置竞品」的提及声量中，自有品牌所占比例。越高表示 AI 更愿意讨论你而非竞品。

**推荐公式（按提及次数，非按回复条数）**：

```text
总声量 = Σ mention_count_own + Σ_{c∈竞品} mention_count_competitor(c)

声量份额 = Σ mention_count_own / 总声量    （总声量 > 0）
```

**按回复先算再平均（可选，减少单条超长列表偏差）**：

```text
sov_r = mention_count_own(r) / (mention_count_own(r) + Σ mention_count_competitor(r))
声量份额 = mean(sov_r) over r where 分母 > 0
```

**与现有 `leaderboard.share_of_voice` 的差异**：

- 现状：`mention_counts[label] / N`，即「有多少条回复提到了该实体」——这是**可见度型份额**，不是声量份额。
- 改造：在 `build_leaderboard` 或新函数 `build_share_of_voice` 中改用 `mention_counts` 累加次数；`leaderboard` 可同时返回 `visibility_share` 与 `mention_share` 避免破坏兼容。

**边界**：

- 某条回复各方均为 0 次提及时，该条不参与 SOV 平均。
- 仅配置竞品、未提及时总声量为 0 → 返回 `null`。

---

### 4.4 平均排名（Average Rank）

**含义**：在单条回答正文中，按品牌/竞品**首次出现字符位置**排序得到名次；对所有「提及了自有品牌」的回复求平均。数值越小越好（1 表示最常最先被提到）。

**单条回复名次算法**：

1. 候选集合 = 自有名称（canonical + aliases 或 domain）+ 全部 `CompetitorBrand` + 需要参与排名的 `CompetitorDomain`（可选）。
2. 对每个候选取 `first_index`（已有 `rank_hints_first_index`）。
3. 仅保留 `index != null` 的候选，按 index 升序排序，名次从 1 开始赋值。
4. `rank_own` = 自有实体中最佳（最小）名次。

**聚合公式**：

```text
平均排名 = mean(rank_own(r)) over r ∈ R where rank_own(r) is not null
```

**实现要点**：

- 现状 `rank_hints_first_index` 存的是字符偏移，不是名次；需在解析收尾增加 `rank_own` 计算。
- 未提及自有品牌时不计入平均（避免拉低）。
- 前端可展示「#1.8」或保留一位小数；竞品对比可用同结构 `rank_by_label` 分布。

---

### 4.5 引用率（Citation Rate）

**含义**：在提及自有品牌的前提下（或按产品选择：占全部回复），有多少比例伴随指向**自有域名**的来源链接——衡量可信度与导流潜力。

**推荐公式（与产品文案「品牌提及 + 链接」对齐）**：

```text
引用率 = |{ r : mentions_own(r) ∧ cited_own_domain(r) }| / |{ r : mentions_own(r) }|
```

**备选（占全部回复，更严格）**：

```text
引用率 = |{ r : cited_own_domain(r) }| / N
```

**实现要点**：

- `domain` 主体：`cited_own_domain` 已实现（`url_hosts` 后缀匹配根域）。
- `brand` 主体：需在 `Subject` 或租户配置中增加 `primary_domain`，否则引用率仅统计正文域名出现，不统计链接。
- V1：解析 `citation_urls_own`，区分「提及句附近 200 字内出现链接」提高精度。

**与现状**：`build_overview().cited_own_domain_rate` 使用 `cited_own / N`（占全部回复），与上式分子分母不同；应拆字段 `citation_rate`（提及条件下）与 `citation_coverage`（全量）。

---

### 4.6 情感倾向（Sentiment）

**含义**：AI 在提及自有品牌时的态度；数值越高越正向。需区分于整段回答情感。

**推荐实现（分阶段）**：

**MVP（规则）**：

1. 将 `raw_text` 按句切分（中英文句号、换行）。
2. 仅保留包含任一 `own_names` 的句子集合 `S`。
3. 对 `S` 拼接后跑现有词典 `_crude_sentiment` → `sentiment_own`。
4. 映射分数：`positive=1.0`，`neutral=0.5`，`negative=0.0`。

```text
情感得分 = mean(sentiment_score_own(r)) over r where mentions_own(r)
```

**V1（模型）**：

- 二次调用小模型或结构化输出，对「品牌相关片段」打 1~5 分再归一化。

**与现状**：`sentiment_counts` 对整段统计；应新增 `sentiment_own_counts` / `sentiment_score_avg`。

## 5. 聚合服务与 API 设计

### 5.1 扩展 `build_overview`

建议返回结构（示例）：

```json
{
  "window": { "from": "...", "to": "..." },
  "response_count": 120,
  "filters": { "platforms": ["deepseek"] },
  "visibility_rate": 0.65,
  "mention_intensity": 1.12,
  "share_of_voice": 0.41,
  "average_rank": 1.8,
  "citation_rate": 0.33,
  "sentiment_score": 0.71,
  "sentiment_own_counts": { "positive": 40, "neutral": 25, "negative": 3 }
}
```

### 5.2 新增/调整端点

| 端点 | 说明 |
|------|------|
| `GET /subjects/{id}/overview` | 承载六大指标（上表） |
| `GET /subjects/{id}/visibility-analysis` | 可见度页：可见度 / AI 提及 / **声量份额** / **平均排名** 的排名、趋势与上一周期对比 |
| `GET /subjects/{id}/leaderboard` | 保留竞品对比；`share_of_voice` 改为声量口径，另加 `visibility_share` |
| 查询参数 | `from`、`to`（已有）；`platform`（可重复）；`topic_id`（可选） |

### 5.3 实现顺序（建议）

1. **解析增强**：`mention_count_own`、`mention_counts_competitors`、`rank_own`（`parser.py`）。
2. **品牌情感**：句子级 `sentiment_own`、`sentiment_score_own`。
3. **聚合函数**：`compute_subject_metrics(rows, subject) -> MetricsBundle`（`analysis.py`）。
4. **API 对齐**：扩展 `overview`；修正 `leaderboard` 声量公式。
5. **回填（可选）**：管理命令对历史 `raw_text` 重新 `parse_llm_output` 写入 `parsed`。
6. **前端**：`OverviewPage` 绑定新字段与文案。

## 6. 质量与已知局限（需在 UI 脚注披露）

| 项 | 说明 |
|----|------|
| 启发式解析 | 子串匹配无法处理代词、表格、多语言变体；V1 可引入 NER 或 LLM 结构化抽取 |
| 排名 | 基于首次出现位置，不等同于「推荐列表中的第 N 项」 |
| 情感 | 词典法对反讽、上下文无效；品牌主体需绑定域名才能算引用率 |
| 渠道 | 多平台样本量不均时，应用加权 SOV 或分平台展示 |
| 采样偏差 | 指标仅反映已配置 Prompt 的问答分布，不代表真实用户提问全集 |

## 7. 测试建议

- **单元测试**：构造固定 `raw_text`，断言 `parsed` 各计数字段与 `rank_own`。
- **聚合测试**：3~5 条 mock `LLMResponse.parsed`，手算可见度、SOV、平均排名与 API 一致。
- **回归**：`brand` / `domain` 主体、零提及、仅竞品提及、仅链接无正文提及等边界。
