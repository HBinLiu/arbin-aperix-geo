# 后端联调

> 代码位于 **[../backend/](../backend/)**；以下命令默认在 **`backend/`** 目录执行（与前端目录隔离）。  
> 产品文档索引：[README.md](./README.md)

## 前置条件

- Python 3.12+
- Docker：在**仓库根目录**执行 `docker compose up -d`，启动 [docker-compose.yml](../docker-compose.yml) 中的 PostgreSQL 与 Redis
- 在 `backend/` 下复制 `.env.example` 为 `.env`，填写 `DEEPSEEK_API_KEY`

## 安装与迁移

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -e '.[dev]'
export PYTHONPATH=src
cp .env.example .env   # 按需编辑
python -m alembic upgrade head
```

## 进程

**一条命令（API + Worker + Beat）：**

```bash
cd backend
export PYTHONPATH=src
bash scripts/start_backend.sh
# 本地热重载：bash scripts/start_backend.sh --reload
# 仅 API + Worker：bash scripts/start_backend.sh --no-beat
```

或分别开终端：

**API：**

```bash
cd backend
export PYTHONPATH=src
python -m aperix_geo
# 或：aperix-geo-api（需已 pip install -e '.[dev]'）；端口等见 .env 中 API_HOST / API_PORT
# 仍可用：uvicorn aperix_geo.main:app --reload --host 0.0.0.0   # 不写 --port 时默认 8000
```

**Celery Worker（采样必开）：**

```bash
cd backend
export PYTHONPATH=src
celery -A aperix_geo.celery_app.celery_app worker --loglevel=INFO
```

**Celery Beat（定时自动采样，可选）：**

```bash
cd backend
export PYTHONPATH=src
celery -A aperix_geo.celery_app.celery_app beat --loglevel=INFO
```

## 采样

仅开 API 不会执行采样——Worker 负责调 LLM；Beat 负责按间隔自动 enqueue（须与 Worker 同开）。

| 组件 | 必须 | 说明 |
|------|------|------|
| Worker | ✅ | job 从 `queued` 变为实际调用 |
| Beat | 可选 | 品牌页配置间隔后自动触发 |
| API | 按需 | 前端轮询 job / pipeline-status |

`.env`：`DATABASE_URL`、`REDIS_URL`、`CELERY_BROKER_URL`、至少一个 `*_API_KEY`（如 `DOUBAO_API_KEY`）。

**本地手动触发：**

```bash
cd backend && export PYTHONPATH=src
python3 scripts/sampling_trigger.py --list   # 列出 subject
python3 scripts/sampling_trigger.py          # 触发最新 subject（不需 API）
```

**其它入口：** Setup finalize · 脚本 `sampling_trigger.py` · 开发调试 `SAMPLING_DEBUG_*` + `POST .../dev/subjects/{id}/sampling-jobs`（见 `backend/.env.example`）。

**排错：** job 一直 `queued` → 未开 Worker；创建失败 → 无 enabled prompt 或未配 API Key；定时不动 → 未开 Beat 或间隔为「关闭」。

## 前端（可选）

仓库 **`frontend/`** 已提供 Vite + React：**`/`** 为对外官网骨架（右上角 **登录** → **`/auth/login`**），**`/app`** 为控制台首页（无 JWT 重定向登录）；**邮箱**：先 **`/auth/register`**（邮箱验证码 + 密码），再 **`/auth/login`** 用邮箱+密码；**手机号**：仅在登录页短信验证码，**未注册号码验证通过即自动开通**。默认 **`ENV=development`** 时手机验证码随机生成并在 **`dev_code`** 回显、不调短信网关；生产设 **`ENV=production`** 且配置 **`SMS_ALIYUN_*`** 走阿里云。开发环境下邮箱验证码同样在 **`dev_code`** 回显。

## 认证：邮箱注册 + 双通道登录（推荐联调）

依赖 **Redis**（与 `REDIS_URL` 一致）。数据库需执行迁移 **`002_otp`**（用户表增加 `phone`，`email` / `hashed_password` 可空）。

1. `POST /api/v1/auth/send-code` — body：`{ "purpose": "register"|"login", "channel": "email"|"phone", "target": "..." }`  
   - **`purpose=register` + `channel=email`**：未注册邮箱发 **注册** 验证码（邮箱通道仍为占位：日志 + 可选 `dev_code`）。  
   - **`purpose=register` + `channel=phone`**：返回 **400**（手机号请在登录页用短信验证，自动注册）。  
   - **`purpose=login` + `channel=email`**：**不发验证码**（防误用）；响应提示使用密码登录。  
   - **`purpose=login` + `channel=phone`**：**始终发登录验证码**（含未注册号码，用于「验证即注册」）；**开发环境**（`ENV=development|dev|local`）不写真实短信、随机验证码并回显 **`dev_code`**；**生产**在 `ENV=production` 且开启阿里云时走 **SendSms**。失败 **503**。  
2. `POST /api/v1/auth/register-with-otp` — 仅邮箱：`tenant_name`、`channel`（固定 `email`）、`target`（邮箱）、`code`、`password`（≥8）→ `access_token`  
3. `POST /api/v1/auth/login` — 邮箱 + 密码登录（可多租户邮箱时同原逻辑传 `tenant_id`）→ `access_token`  
4. `POST /api/v1/auth/login-with-otp` — 仅手机：`channel`（固定 `phone`）、`target`、`code`，可选 `tenant_name`（首次自动注册时的工作区名）→ `access_token`  

仍保留：`POST /api/v1/auth/register`（邮箱+密码直注册，无验证码）。

## 诊断四步流水线（联调顺序）

官方四步：**Verify → Dispatch → Clean → Analysis**。详见 [05-诊断流程.md](./05-诊断流程.md)。

| 步 | 阶段 | 本仓库 MVP 联调要点 |
|----|------|---------------------|
| — | **平台** | 登录拿 `access_token`（见上） |
| 01 | **Verify** | 主体、竞品、主题、提示词；可选 `discover-*` / `generate-prompts` |
| 02 | **Dispatch** | Setup finalize / Beat / 脚本 + Worker |
| 03 | **Clean** | Worker 内 `parser` 写 `parsed`；`GET /responses/{id}` 查看 |
| 04 | **Analysis** | `overview`、`rank` 等（指标见 [06-分析指标.md](./06-分析指标.md)） |

### 01 Verify — 配置与提示词

1. `POST /api/v1/subjects` — 创建 `domain` 或 `brand` 主体  
2. `PUT /api/v1/subjects/{id}/competitors` — **brand 主体至少填一个竞品品牌名**  
3. `POST /api/v1/subjects/{id}/topics` — 创建主题  
4. `POST /api/v1/subjects/{id}/prompts` — 在主题下创建提示词  
5. （可选）设置向导 API（UI：设置 → **选竞品** → **审主题** → 确认提示词）  
   - `POST /api/v1/subjects/setup/sessions` — 画像 + 预生成监测主题  
   - `POST /api/v1/subjects/setup/sessions/{session_id}/competitors` — 竞品搜索  
   - `POST /api/v1/subjects/setup/sessions/{session_id}/prompts` — 确认主题 + 生成问句  
   - `POST /api/v1/subjects/setup/sessions/{session_id}/finalize` — 落库  

### 02 Dispatch — 采样任务

> 运行要求见上文 [采样](#采样)：Worker 必开；Beat 仅定时采样需要。

6. `POST /api/v1/subjects/setup/sessions/{session_id}/finalize` — 落库并自动创建采样 job（需 Worker）  
   或本地：`python3 scripts/sampling_trigger.py` / 开发调试 `POST .../dev/subjects/{id}/sampling-jobs`（`SAMPLING_DEBUG_*`）  
7. `GET /api/v1/sampling-jobs/{job_id}` — 轮询状态  

### 03 Clean — 解析结果

8. `GET /api/v1/responses/{response_id}` — 证据（`raw_text` + `parsed`）  
    - 实现：`backend/src/aperix_geo/services/parser.py`（采样成功后自动执行）

### 04 Analysis — 指标聚合

11. 分析聚合（部分 **POST** + JSON body，部分 **GET** + query；字段均为 `start_date`、`end_date` 及可选 `entity_id`、`platform`、`topic_id` 等，时间 ISO8601 带时区）  
    - `POST /api/v1/subjects/{id}/overview`  
    - `POST /api/v1/subjects/{id}/analysis/visibility`  
    - `POST /api/v1/subjects/{id}/analysis/topics` — 主题表现  
    - `POST /api/v1/subjects/{id}/analysis/prompts` — 提示词表现（可选 `sort_by`、`order`）  
    - 其余见 [06-分析指标.md](./06-分析指标.md) §5.4（`GET`）  
    - 实现：`backend/src/aperix_geo/services/analysis.py`
